# D24 LangGraph API verification

Verified 2026-10-14 against official live docs, PyPI metadata, and GitHub tag `1.2.15`; read D24 and issue14 first. **Recommend `langgraph==1.2.15`**, currently published non-prerelease/non-yanked latest, uploaded 2026-10-12; metadata requires Python >=3.10 and explicitly classifies Python3.12. This is documentation/source verification, **not installation, runtime, or product validation**. No model/provider calls or repository changes performed. [PyPI release](https://pypi.org/project/langgraph/1.2.15/), [exact metadata](https://pypi.org/pypi/langgraph/1.2.15/json).

## Minimum API and graph shape

Use `TypedDict`, `StateGraph`, `START`, `END`, `add_node`, `add_edge`, `add_conditional_edges`, and `compile`. Async node functions return partial state dictionaries; unannotated state keys use replacement semantics. A readable design is START → validate → plan → conditional Global evidence / retrieved evidence → generate → finalize → END. Supply an explicit path map or Literal return annotation so graph rendering accurately shows the branch. Keep ContextPacker extraction and AnswerGenerator's low-on-length retry inside their existing modules; do not configure a graph RetryPolicy that could replay streamed deltas or history writes. [Graph guide](https://docs.langchain.com/oss/python/langgraph/graph-api), [1.2.15 StateGraph source](https://github.com/langchain-ai/langgraph/blob/1.2.15/libs/langgraph/langgraph/graph/state.py).

`compile()` is required and validates graph structure. Its defaults are checkpointer/cache/store=None, interrupts=None, debug=False. For this root graph, None means no persistence; `compile(checkpointer=False)` explicitly prevents future inherited checkpointing too. `invoke`/`ainvoke` are completion APIs; invoke defaults to values output. Use `astream` for the public SSE path. A compiled StateGraph defaults to updates streaming, although base Pregel defaults to values: **always explicitly select custom**. Tagged source's graph retry default is empty (disabled). [StateGraph source](https://github.com/langchain-ai/langgraph/blob/1.2.15/libs/langgraph/langgraph/graph/state.py), [Pregel source](https://github.com/langchain-ai/langgraph/blob/1.2.15/libs/langgraph/langgraph/pregel/main.py).

## Application events and dependencies

Inside async nodes obtain `writer = get_stream_writer()` and call `writer(existing_event)` for each existing stage/citation-map/thinking/reset/token event. In the adapter use `graph.astream(inputs, stream_mode="custom", version="v1")` and yield payloads unchanged. With a single string mode, subgraphs=False (default), and v1 (default), tagged `_output` yields the original payload, including application Event objects. v2 instead wraps it as `{type, ns, data}`. Writer calls are synchronous; custom mode streams during node execution rather than waiting for node completion. Official docs expressly support arbitrary native LLM APIs via custom streams, so no LangChain model integration is needed. Python <3.11 writer/context-propagation restrictions do not apply to Python3.12. [Streaming guide](https://docs.langchain.com/oss/python/langgraph/streaming), [writer source](https://github.com/langchain-ai/langgraph/blob/1.2.15/libs/langgraph/langgraph/config.py), [output/source](https://github.com/langchain-ai/langgraph/blob/1.2.15/libs/langgraph/langgraph/pregel/main.py).

Documented transient dependency route: `StateGraph(State, context_schema=Context)`; pass `context=Context(...)` into `astream`; inject `runtime: Runtime[Context]` into nodes and read `runtime.context`. Runtime defaults context/store to None and stream_writer to a no-op outside active custom streaming. Service/Document belong here rather than graph state. A graph built per request with captured closures is a simpler design alternative (ordinary Python inference, not a special LangGraph contract); avoid mutable request data captured by a shared graph. [Runtime guide](https://docs.langchain.com/oss/python/langgraph/graph-api#runtime-context), [runtime source](https://github.com/langchain-ai/langgraph/blob/1.2.15/libs/langgraph/langgraph/runtime.py).

## Cancellation and top three risks

1. **Cancellation/close:** tagged runner marks async node tasks cancel-on-exit; AsyncBackgroundExecutor cancels marked tasks and awaits tracked tasks. However AsyncPregelLoop.__aexit__ creates an exit task and, if cleanup itself is cancelled, attaches that task to CancelledError.args for the caller to await. This establishes cleanup intent, not guaranteed application/SSE disconnect safety. Own and close the graph iterator explicitly in the public generator's finally; propagate cancellation, close native answer/gateway iterators, and retain `_asking` cleanup outside success-only finalize. Avoid detached producer tasks. [Runner](https://github.com/langchain-ai/langgraph/blob/1.2.15/libs/langgraph/langgraph/pregel/_runner.py), [executor](https://github.com/langchain-ai/langgraph/blob/1.2.15/libs/langgraph/langgraph/pregel/_executor.py), [loop](https://github.com/langchain-ai/langgraph/blob/1.2.15/libs/langgraph/langgraph/pregel/_loop.py).

   Required targeted runtime regression: actual compiled graph blocked mid-delta; separately cancel pending `anext`, close the paused public generator, and disconnect SSE. Assert node/native-stream finally markers, no pending producer/LLM/exit tasks, `_asking` cleared, no history/final, and next ask works. Include repeated cancellation during cleanup. These tests remain implementer's work.

2. **Event/commit timing:** writer delivery is queued. Preserve baseline final/history ordering explicitly and test close immediately after final; do not assume yielding a final event proves the adapter consumed it or graph reached END.

3. **Dependency expansion:** metadata mandates langchain-core>=1.4.7,<2; langgraph-checkpoint>=4.3.0,<5; langgraph-prebuilt>=1.1.0,<1.2; langgraph-sdk>=0.4.6,<0.5; pydantic>=2.7.4; xxhash>=3.5.0, plus their transitive dependencies. Installing checkpoint/prebuilt/sdk does not require using persistence, agents, hosted services, LLM/loader/retriever wrappers. Lock resolved dependencies and verify clean Python3.12 installation separately. [Exact metadata](https://pypi.org/pypi/langgraph/1.2.15/json).
